# Quickstart & Validation: SoundCloud Crate Sorter

**Phase 1 output.** How to set up, run, and prove v1 works end-to-end. Implementation details live in
[data-model.md](./data-model.md), [contracts/ports.md](./contracts/ports.md), and `tasks.md`
(generated by `/speckit-tasks`). This is a validation guide, not a build script.

## Prerequisites (macOS Apple Silicon)

- **Rust** (stable) + Cargo.
- **Node.js** + a package manager for the `ui/` React app; Tauri v2 CLI.
- **Homebrew system libs** for audio analysis:
  ```sh
  brew install libkeyfinder   # pulls fftw
  brew install aubio
  brew install yt-dlp
  ```
  Verify `pkg-config --exists libkeyfinder && echo ok` returns `ok` (the `libkeyfinder-sys` build
  probes it).
- **Claude API key** in the environment for the genre/vibe classifier (never committed, never logged).

## Setup

```sh
# from repo root
cargo build            # builds domain, application, adapters, app (Tauri core)
cd ui && <pm> install  # frontend deps
cd .. && cargo tauri dev   # runs the desktop app
```

If the `libkeyfinder-sys` build fails to link, that is the known FFI risk (research.md R4). The
`AudioAnalyzerPort` isolates it — the metadata-only path (US1/US2) still runs without it.

## Validation scenarios (map to spec User Stories & Success Criteria)

### V1 — Scan + auto-classify (US1, no download needed)

1. Enter a public SoundCloud profile URL with liked tracks; run **Scan**.
2. **Expect**: every unique liked track appears (duplicates/reposts collapsed — FR-003); each track
   shows a proposed crate + confidence; crates exist only for genres present (FR-009).
3. **Passes SC-001** when ≥85% of tracks land in a crate you accept without moving it.

### V2 — Manual triage (US2)

1. Lower the confidence threshold if needed so some tracks fall into the queue.
2. Open **Triage**. **Expect**: sub-threshold tracks appear as swipe cards with audio preview, a top
   suggestion, and alternative chips; a table view lists the same queue.
3. Accept / pick alternative / open full picker / create a crate / defer. **Expect**: each action
   assigns and removes the card; decisions persist — re-scan does NOT re-present decided tracks
   (FR-018).
4. **Passes SC-002** when each card is decided in <10 s on average.

### V3 — Audio analysis (US4, opt-in download)

1. Enable **Download** (off by default), run analysis on a small set.
2. **Expect**: each downloaded track gains BPM, Camelot key, and energy (deterministic — same file
   twice → same values); crates gain an energy sub-role; undownloadable tracks stay metadata-only and
   are reported, never blocking (FR-007).
3. Cross-check a few keys against Mixxx before trusting at scale (research.md R4 risk).

### V4 — Local / Rekordbox export (US5)

1. Run **Export → Local** on classified crates with downloaded audio.
2. **Expect**: one folder per crate containing the audio files + an M3U8; each file's ID3 tags carry
   genre, BPM, key, energy, vibe (FR-023); tracks without local audio are skipped and reported
   (FR-024).
3. Import a crate folder into Rekordbox. **Passes SC-004** when it imports with no rework.

### V5 — Idempotent re-run (SC-006, Principle IV)

1. Add a new like on SoundCloud, re-run **Scan**.
2. **Expect**: only the new track is processed; prior classifications/triage decisions are untouched;
   no duplicates created.

### V6 — Audit answerability (Principle VII)

1. Pick any classified track, open its **audit trail**.
2. **Expect**: the trail shows why it's in its crate (genre from tag vs AI, confidence, any manual
   override with from→to crate + timestamp) and every download/export outcome. No tokens/secrets
   appear anywhere in logs or trail.

## Automated verification

```sh
cargo test              # use-case unit tests (in-memory port fakes) + port contract tests
cargo test --features real-adapters   # contract tests against real adapters (needs system libs + network)
```

- Every use case has isolation tests with in-memory fakes (no network/FS/AI/DB).
- Every port has a contract test run against BOTH the in-memory fake and the real adapter
  (Principle VI).

## Out of v1 scope (do not validate here)

- SoundCloud playlist export (US3 / FR-019–021) — deferred to v2 (research.md R3).
